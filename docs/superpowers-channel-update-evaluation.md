# 0.5.11：Superpowers 渠道迁移与依赖更新评价

## 问题证据与责任层

0.5.10 在 Codex 中固定使用已下架的 openai-api-curated 渠道，并依赖本地配置判断
启用状态。官方 6.4.1 仍包含三项必需技能，但新渠道为 openai-curated-remote，
原生清单中的 enabled 状态不一定写入 config.toml。旧缓存存在也不能证明当前插件有效。
这是宿主适配与安装升级闭环问题，不改变业务合同、托管状态机或验收标准。

## 基线、假设与复用

- 基线：0.5.10 的全量 80 文件、577 测试通过，但真实 doctor 的三项技能失败。
- 复用现有依赖模块、update 入口、Hook 和失败汇总，不新增第二套更新器。
- 假设：读取原生插件目录、限定官方渠道并验证当前启用版本文件，可消除错误检测。
- 升级先安装 CLI，再由新 CLI 处理依赖兼容；避免旧进程和 PATH 中旧 shim 使用过期规则。

## 实例与前后结果

- 红测试首先暴露旧代码缺少新渠道选择能力；实现后定向测试通过。
- 新插件无 config.toml 启用段：按原生 enabled 清单正确通过。
- 插件已安装、available 为空：仍从 installed 找到插件并执行升级。
- 第三方同名包、预发布版本、安装返回旧版本、未确认版本的已安装提示：拒绝通过。
- 当前版本缺技能、只有旧缓存或原生清单离线：不借旧文件假绿。
- Claude 已安装：仍执行 plugin update；模拟测试覆盖后，按用户要求补充实机验证。
- 带包升级与日常 apply：新 CLI 接管依赖；子进程失败向上传递，不写成功节流状态。
- 本机真实安装和重复升级确认 Superpowers 6.4.1，三项技能检查通过。
- 最终全量 81 文件、585 测试通过，含 installed-only 升级回归；Lint 和构建通过。
- 实机依赖更新成功，OpenSpec 全局包更新至 1.13.1；doctor 所有检查通过。
- Claude 实机从 6.0.2 更新至 6.4.1，原生清单 enabled=true，三项技能文件存在。
  完整更新刷新 15 个技能、22 个脚本、10 个 Hook 和 MCP；doctor 52 项全部通过。
  Codex doctor 63 项全部通过；业务项目 NVM 环境的 OpenSpec 也已同步至 1.13.1。

## 范围与结论

日常策略仍默认 check，只检查 npm 更新并提示插件刷新；apply 或手动带依赖更新才
真正升级 OpenSpec、Superpowers 和 Superflow 资产。没有擅自开启后台自动修改。
双语帮助、安装说明同步；两个宿主均已实机验证更新和环境检查，但未调用模型执行业务任务。
不改充电业务代码，不声称本轮修复了业务事故，也不涉及新的 Agent 语义质量评价。

若官方清单格式或安装路径再次变化，应停止更新并报告错误，修正适配后重试；
不得退回“目录存在即成功”或跳过三项必需技能。必要时回滚 CLI，保留现有插件及诊断证据。
