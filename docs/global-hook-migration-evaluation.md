# 全局旧 Hook 迁移评价

## 问题证据与责任层

Codex `Stop` 同时注册了旧的 `bash scripts/hooks/stop-compile-check.sh` 与当前
`superflow-java-stop-hook.sh`。前者在 operator-api 中不存在，结束任务时可能返回 127。
0.5.14 的项目级迁移不会触碰全局配置；当前全局 Codex、Claude 配置分别有
12、17 条已知旧相对路径注册。部分其他项目仍有这些脚本，故其全局删除是明确的
能力取舍，不能把“当前仓库缺失”误称为“所有项目都缺失”。用户选择以全局
Superflow Hook 为准，接受旧 Hook 在其他项目不再由全局触发。

责任层是现有 Hook 迁移 CLI，不新增 Hook、Skill 或第二套安装状态。普通
`update` 不静默删除来源不明的注册；只读审计后显式 `--scope global --apply`
才修改 home 下的两份配置。

## 假设、实例与结果

| 实例 | 预期与结果 |
|---|---|
| Codex 12 条、Claude 17 条旧白名单命令 | 全局审计准确列出；执行后候选均为 0 |
| 相似命令带自定义参数或未知脚本 | 保留，不由文件名模糊匹配删除 |
| 两宿主及项目配置并存 | 只改指定宿主的全局文件；项目配置保持原字节 |
| 重复迁移 | 第二次 `changed=false`，不再生成备份或改写文件 |
| 文件是符号链接、配置损坏 | 沿用现有安全读取逻辑，阻止自动迁移 |

本机显式迁移已备份 `~/.codex/hooks.json`、`~/.claude/settings.json`，仅删除
29 条白名单旧注册。Codex 17 条、Claude 18 条其他 Hook 保留；第二次执行均无变更。
源代码安装闭环需要重启宿主才能让当前进程重新读取 Hook 配置。
本轮全量测试 **95 个文件、656 个用例通过**；构建、ESLint、设计宪章门禁和
`skill-audit --strict` 通过。一次全量耗时不能推断性能趋势；迁移不增加运行时
Hook 数量，减少全局无效命令尝试。

风险：少数仍依赖旧全局 AKE Hook 的项目将失去这些全局注册；项目级自有配置不变。
回滚时从迁移生成的同目录 `.superflow-migrate-*.bak` 恢复对应配置，并重启宿主。
若白名单误删自定义命令、备份缺失、作用域串扰或重复执行改写配置，应停止发布并修复。
