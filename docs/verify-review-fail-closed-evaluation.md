# 完整 SDD 验证阶段入口凭证检查评价

## 问题、基线与责任层

operator-api 的 15 页审计字段回放显示：0.5.14 的逐用例 lint 在传入
`document-review.json` 时会拒绝 13/15 回填；完整 workflow 缺该文件时，
verify guard 却只传 `tests.md`，使同一份 C 类用例报告绕过逐入口核对。
这是确定性门禁的失败安全缺口，不是业务断言或 Agent 语义判断问题。

变更前的定向回归先失败：完整 workflow 缺入口凭证时，没有出现对应阻断信息。
假设：在现有 verify guard 中要求完整 workflow 的入口凭证存在，并继续调用现有
lint 的 `--review`，即可让缺凭证与 13/15 缺回填均失败；Quick/Hotfix/Tweak
不增加完整 SDD 文档负担。

## 实例与结果

| 实例 | 预期与实测 |
|---|---|
| 完整 SDD 缺 `document-review.json` | verify 阻断并指出返回 docs 入口评审 |
| 冻结 15 项、只回填 13 项 | 现有 lint 收到 `--review`，指出缺失 C14/C15 |
| 冻结 15 项、完整回填 15 项 | 中英文 guard 均可通过 verify |
| Tweak 没有完整入口凭证 | verify 保持通过，不引入错误阻断 |

只调整中英文两个既有 guard 镜像与定向测试；未增加 Skill、Hook、Prompt、状态、
Agent 调用或模型轮询。入口全集、精确 Mapper 和非空同 ID 断言仍由
`source-contract` 评审与真实验收负责，脚本只判断凭证存在及逐项回填。

全量回归为 **95 个文件、652 个用例通过**；构建、ESLint、设计宪章门禁与
`skill-audit --strict` 通过。对比 0.5.14 发布时的 650 个用例，本轮新增
两个定向用例；单次运行耗时不能推断总体性能。未重跑 operator-api 的浏览器
或测试集群，本轮结论只针对 Superflow 的确定性门禁行为。
`npm pack --dry-run` 成功，402 个包内文件含中英文 guard 与现有报告 lint。
定向回归分别执行两个 guard 镜像，结果一致。

结论：所观察到的凭证缺失绕行已堵住；来源清单的语义完整性与真实证据质量
仍须 Agent 审查。额外成本为一次本地文件存在性检查，没有新增调用或长期状态。

回滚条件：完整 workflow 的合法验收被误阻断、Quick 路径被错误要求完整凭证，
或 Codex/Claude 安装后的两个 guard 行为不一致。保留故障注入证据后回滚此门禁，
不得通过放宽逐项 lint 取得假通过。

## ECC 五维与独立代码评审吸收（2026-10-12）

基线为 0.5.21 / 146b2cd。用户提供 ake 的分档与独立评审记录后，核对本仓发现：
CLI 仅凭 Mapper/Controller 路径或文件数给 risk.tier，verify 直接据此选深度；五维
散落在专项条目，缺隔离包与主 Agent 合并的可执行形状。只读 A/B/C 基线探针证实
只读 Mapper 会被路径提示推 high，普通文件的原子占用又可被提示 low；完整聊天
上下文不能证明新鲜视角。新增定向测试先出现 9 项失败（提示属性 2、两语托管入口
2、四组安装 4、双语帮助 1），没有先修改期望掩盖基线。

责任层：既有 review-coverage 提供确定性清单/路径提示；reviewer-checklist 是五维、
语义分档、隔离包和 finding 复核的唯一规范；superflow-verify 路由，主 Agent/Host
持有真实风险、完整覆盖和最终结论。普通裸 diff 不创建 SDD 状态；完整 SDD 仍按
冻结合同交付。托管只通过随包 ASSETS_DIR 引用同一规范，三个 Agent JSON、预算、
状态迁移和 Runner owner 未改变。没有新增 Skill/Hook/长期状态/模型轮询，未引入
固定代理数、模型名称、另一套严重度或需求评审入口。

假设：把路径判断显式标为 path-hint + requiresSemanticAssessment，并在既有入口
要求主 Agent 按真实源码记录分档依据、使用必要上下文隔离与逐维覆盖，可避免把
机械信号冒充语义裁决，也避免全绿自述替代独立检查。保持风险未知补证据、权限、
原始证据、历史有效证据与现有报告锚点门禁；五维充分性不由字符串或计数裁决。

代表实例与结果：A 为只读参数化 Mapper 过滤，无契约/schema/写路径变化且消费链
已核对，允许提示 high 与实际 medium 不同并记录原因。B 为普通单文件新增原子
占用/共享状态写入，实际 high 不被路径 low 降级。C 为实现者声称全绿，reviewer
仅接收准确 diff、合同、适用规则和必要原始证据路径，主 Agent 核实、证伪、按根因
与影响合并。三例更新后探针通过。另以 fork_turns=none 的新鲜 reviewer 审查准确
隔离包，22 个变更文件哈希匹配（排除用户原 HTML），五维均 CHECKED，无实质
finding；路径枚举默认排除的测试仍实际审查。主 Agent 对照真实差异接受该结论。

验证：全量 103 文件、774 项通过；最终受影响五文件 33 项通过。Lint、构建、全局/
托管设计门禁、严格 Skill 审计 16/16、零英文镜像缺口通过。编译 CLI 的中英文 help、
文本提示与兼容 JSON 冒烟通过，risk.tier/reasons 保留，仅追加提示属性。原报告状态
与锚点校验未放宽；独立性、实际深度和五维质量仍是主 Agent 的语义检查。

npm 实际打包 402 文件，在一次性 consumer 安装 97 个生产依赖（禁用 postinstall
以免更改真实宿主），从安装包运行 CLI 并生成两语 Host prompt，确认其规范路径在
包内可读。随后用包内真实 deploySkill 验证 Codex/Claude × 中英文四组两轮安装，
解析同一五维入口并保留相邻自定义技能。源码安装也使用相同四组回归。真实本机
Codex 的 pipeline/verify 两项已通过既有部署原语同步，39 文件与源码一致；写入前
未知文件与自定义漂移均零，临时备份保留。未读取或修改本机 Claude/agents 技能。

托管宪章回查：裁决仅新增 Host 语义职责的明确指南，Executor 运行/清理与 Runner
状态职责未串层；协议 Schema、有效历史证据/negative 防绕过、晋升、供应商恢复、
阶段/preflight、MCP wait/唯一交付等既有回归均在全量集合通过。没有业务 API/DB/
测试策略塞入托管 Prompt，未调整进程 helper 或增加公共灾难认证。

结论：所观察的分档、五维与隔离形状缺口在本次范围内关闭；不宣称已经证明所有
业务缺陷都会被发现。模型 Token/费用未提供，没有同等任务成本样本，不能推断
调用、效率或成功率普遍改善。本次未升级版本或发布 npm；本机只同步技能资产，
新增 CLI 提示与托管 Prompt 的真实全局运行时仍待正式安装新版。新会话需重载技能，
发布安装后需按既有指纹门禁重启 Host/MCP；未伪称旧 npm 运行时已更新。

回滚条件：路径提示重新决定语义深度、已知高风险因小 diff 降级、隔离包越出授权
或继承实现聊天、五维未覆盖却晋升完整通过、子代理取代 Host/写状态/运行环境、
双语或安装资产漂移。只回滚或修正对应 owner/指导，不放宽协议与原始证据门禁。
