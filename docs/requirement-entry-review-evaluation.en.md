# 0.5.10: requirement-to-real-entry evaluation

## Evidence, ownership and baseline

A confirmed requirement allowed a child account to create another account under the same
root. A registered creation entry was excluded based on one unrelated filtering dimension;
implementation/tests exercised another correct API while the real actor-specific page used
the old path. An initial remediation suggestion also inverted permission into rejection.
This belongs to source fidelity, scoped exclusion review and real-entry acceptance, not more
technical clarification from the user.

0.5.9 baseline: 79 files / 551 tests passed in 82.43 seconds on this machine. Document audit
checked review lenses, hash markers and prompt links, not requirement-entry coverage.
Dispatch/Hook compared recorded hashes only. Failed coding-ready checks retained old READY.

Hypothesis: extend the existing review receipt and reuse canonical handoff hashing plus source
fingerprints to block missing/stale evidence. Independent Agent review owns business meaning.
No business project, managed state machine or domain-specific runtime rule is changed.

## Representative observations

Regression fixtures block missing requirement-entry pairs, code-only exclusions without
requirement authority, API-only substitution for browser acceptance, cases for the wrong entry,
missing final-state/forbidden-effect assertions, stale source/doc/review content and malformed
coverage. Source-backed exclusions pass. Failed rechecks persist BLOCKED. Intended source edits
remain possible through the Hook; task checkbox/report progress does not invalidate handoff.

Codex/Claude × Chinese/English installation fixtures exposed a macOS `/var` versus
`/private/var` entry-point comparison bug. Realpath comparison fixed it; all four installed
layouts now accept correct inputs and reject source drift without weakening assertions.

Affected checks: 29 document-audit tests plus 13 dispatch/Hook/installation tests passed.
First full run: 573 passed; final full run: 80 files / 577 tests passed in 83.99 seconds,
including the four installation layouts (26 additional tests versus baseline). An intermediate
run alongside build hit an existing guard test's five-second timeout; it passed alone in about
two seconds and the subsequent full run passed without relaxing limits or assertions.
Single-run duration differences do not establish a performance trend. Build, Lint and both design gates pass;
the pack inventory is checked for the shared script and bilingual reference assets.

## Semantic and compatibility boundaries

The primary Agent independently compared the incident's original semantics with the new
review contract: “allowed with root ownership” is not “deny”, and one inapplicable filter
cannot exclude other constraints. Both languages' docs, requirement-review and verify skills
require the corresponding reference. This is not a new business execution or cross-model
semantic benchmark. No charging-system UI/database acceptance was rerun; the business bug is
not claimed fixed. Scripts cannot certify inventory completeness, exclusion validity,
assertion sufficiency or evidence fidelity; these remain independent Agent responsibilities.

Managed communication protocols, state machine, budgets, recovery and cleanup remain unchanged.
Verbal minimal contracts do not acquire document coverage requirements. Existing Run recovery
does not rebuild contracts; a native Hook encountering an old receipt requires review migration.
The added cost is local hashing before dispatch, not another model call or polling loop.
There is no comparable real-task Token/intervention/duration sample, so no such improvement is claimed.

## Conclusion and rollback

Structural omission and content-drift protection is effective; semantic quality needs follow-up
on real tasks. Persistent false blocks, missing installed assets, cross-platform hash mismatch
or progress-only invalidation require pausing rollout and reverting the runtime while retaining
review evidence, not bypassing gates. Track semantic inversions, exclusion mistakes, first-pass
rate, human direction corrections and re-review overhead before expanding the design.
