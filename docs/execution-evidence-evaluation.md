# 逐用例执行证据修复评价

## 问题与责任层

0.5.16 的逐用例 lint 只验证证据文件存在，且接受 HTTP URL；正式 guard 优先调用项目/个人宿主脚本，可能与 CLI 版本不同。集成脚本以全文关键词代替入口对账，历史“未执行”也可能误阻最终有效结果。

匿名基线实测：空文件、不可访问 URL 均 exit 0。新增 15 项回归在修改前为 13 失败/2通过（负例被误放行），修改后全部通过。

只读事故审计确认：Service 对象设值而实际调用的 CAS Mapper statement 漏写；报告声称链路补齐。mock Mapper 成功与恒真占位被计入通过数；真实回调证据主要覆盖另一个服务入口。历史状态为 implement/pending，不能描述为完整集成 PASS。事故脚本对未知 ID、未实现必测 ID、空用例集均 PASS=0/FAIL=0/SKIP=0 且 exit 0。这里仅记录缺陷类型，不公开私有业务数据、源码或凭据。

## 假设、设计与复用

扩展现有 coverage、逐用例表、lint、verify guard 和托管 preflight/final gate，不新建 Skill/Hook/状态机。保留三个托管 JSON 协议。

- 每个 PASS 引用 `superflow.execution-receipt.v1`，原始输出有唯一 case 执行事件；退出码、执行数、入口、断言与凭证一致。
- 运行目标绑定服务、路由、证据等级、当前源码 SHA-256、构建产物 SHA-256 与源码指纹。
- 入口新增/修改持久化字段在已有 coverage 的 entry.persistence 与 case.assertions.persistence 冻结；同业务 ID 前后值及预期值对账。历史 NULL 需明确允许。
- 源码链、精确 Mapper statement、回调轮次和断言充分性由独立 Agent 评审；哈希只证明内容身份，不证明执行诚实。
- 旧证据保留 PARTIAL；完整交付必须最终 PASS。无行为的轻量任务不凭关键词追加数据库义务。
- 包内脚本与已安装脚本同源，正式 CLI 传入本包 lint；宿主资产从安装器同步。

## 评价口径与回滚

本轮为受影响验证及匿名任务级 harness 回放；不声称重新执行真实业务验收或普遍框架认证。计时、Token、模型调用趋势未建立对照，不宣称成本下降。

成功标准：存在性误放行归零；两入口分开核验；遗漏字段的实际值断言失败；有效 partial 可保留、无法完整晋升；历史说明不误阻最终完整覆盖；安装版本重放负例仍拒绝。

若有效凭证被误阻、安装来源漂移、历史恢复协议受损，回滚实现并保留证据，不能放宽冻结业务断言。其余语义边界由独立评审承担。
