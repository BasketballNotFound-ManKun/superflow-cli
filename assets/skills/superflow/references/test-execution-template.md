# 测试执行与结果记录模板

首次验证前实际完整读取 [test-guide.md](test-guide.md)。SDD 构建/用例从
[Runner-Captured Execution](test-guide.md#runner-captured-execution)准备 plan，调用已安装
`superflow-test-report-lint.py --record-execution`。由脚本生成构建/Case receipt、指纹和
脱敏 stdout/stderr；报告链接这些产物，不手填捕获字段。旧证据保留原等级，缺来源为 PARTIAL。

命令、工具链、运行时版本、启动/登录/就绪/停止入口、环境、端口和断言都从当前
tests.md / Quick 批准 Spec 继承。项目已有脚本与测试是执行入口，模板不提供跨项目固定命令。
必测环境缺失记录 BLOCKED/PARTIAL，继续其余已授权工作；不能以本地容器或 Mock
替代明确要求的共享环境。开发交付不自动增加后续发布环境门禁。

按 [Owner 测试策略](test-guide.md#owner-led-test-planning)在现有方案内补强，简述选择理由、
新增分支及本轮证据变化。原 Case 内参数与新 Case/冻结上下文变化沿原合同分别处理。
低风险报告保留实际适用的少量段落；专项证据按冻结用例引用，不逐项列无关的不适用清单。
Quick 沿批准 Spec 记录步骤与实测，不为套用此模板新建 R/E/C 索引或 SDD receipt。

## One current record

报告保留一份当前终态、一张当前 Case 表和一组当前独评/复评引用。当前恢复点随工作推进
更新；旧恢复点、旧结果和旧 Case 表进入明确的 `## 历史记录` / `## History`，或链接既有
历史文件。历史段结束后使用同级标题开始当前记录。新增处置与复评追加独立文件，原
Reviewer 报告保留原状态、finding ID、文件 hash 和结论。

完整 SDD 按 `document-review.json` 的 R/E/C 索引逐项回填，沿既有
[coverage/receipt](document-review-coverage.md)核验；Case 表是当前结果的唯一台账，
详细输出用证据链接承接。数量区分合同 Case、参数分支、测试方法和重复执行。

## 报告形状

以下为现有报告中的章节和字段，按实际适用范围填写：

```markdown
# 测试执行报告

## 历史记录

- 历史结果/恢复点：<既有历史证据或报告的相对链接>
- 原独评与处置：<原报告、Owner 响应及实际复评的链接>

## 当前验证

### 环境与执行

| 项目 | 实际信息与来源 |
|---|---|
| 验证时间 | <本轮时间> |
| 工作区与源码 | <分支/commit及源码身份引用> |
| 构建/运行目标 | <捕获构建凭证；适用时记录实际运行目标> |
| 工具链与环境 | <tests.md指定工具/版本/非秘密配置来源> |
| 执行入口 | <tests.md命令及相对cwd；构建/Case plan链接> |
| 原始输出 | <本轮stdout/stderr、原生测试报告及receipt链接> |

### 当前 Case 结果

| 用例 ID | 入口 ID | 验收级别 | 结果 | 证据路径 |
|---|---|---|---|---|
| <C-ID> | <E-ID> | <冻结级别> | <PASS/FAIL/BLOCKED/PARTIAL> | <本轮receipt路径> |

### 验证范围与未决项

- 目标与实际实现：<目标、实际入口/调用链及版本的对账>
- 测试选择与补强：<理由、新增分支及影响的证据>
- 实际数量：<按单元/接口或后端集成/后端业务链路/浏览器分列集合、通过/失败/跳过/阻塞>
- 未决项：<失败/阻塞Case与finding、原因、影响、处置及所需协同；无则如实说明>
- 外部协同及控制：<未完成联调；提交/发布等实际授权与执行事实>

## Owner Recovery

<当前未完成任务、有效证据、任务自有资源身份和下一动作；已完成则说明>

## Independent Review

| Report |
|---|
| .sdd/reviews/current-code-review.md |

## 当前结论

验证结果: PASS / FAIL / BLOCKED / PARTIALLY_VERIFIED
归档就绪: PASS / BLOCKED
```

当前 Case 结果仅使用 `PASS/FAIL/BLOCKED/PARTIAL`；非 PASS 在未决项解释。当前结论与
Case、receipt、任务及复评一致，完整交付运行当前安装的 lint `--require-complete`。
`verify_mode: full` 还要记录测试环境、分支/commit/构建或镜像、Base URL 和验证时间；
有中英文结果标记时语义必须一致。归档就绪不授予归档、Git 或发布权限。

独评/复评沿 [Reviewer 清单](reviewer-checklist.md#finding-closure)的既有四态报告。
上表引用当前实际返回；原报告与 Owner 响应由新复评报告的 Review Chain 关联，逐 finding
记录复评结果。修后源码变化先重测再实际复评；缺必要独立能力、必测或复评保留 PARTIAL。

## 按适用 Case 留存的详细证据

以下内容写入 Case 证据或链接现有报告，不创建第二张当前 Case 结果表。

### RED/GREEN 与实测断言

适用的 RED 发生在生产代码修改前，记录命令、真实失败输出及其预期业务断言；环境、
编译、凭据或测试代码错误不算正确 RED。GREEN 使用同一命令和原业务预期。
响应、状态及禁止副作用均来自本轮实际观测；执行数、失败、跳过以原生测试输出为准。
发现缺口按 test-guide 补强，不能通过删除或降低断言把失败改成通过。

### 真实入口、数据库与用户操作链

从 tests.md 继承真实参数及来源、鉴权入口、请求/角色/场景和断言。接口必须保留脱敏请求、
响应、DB 查询/持久化前后值及关联日志。数据库结构核查、迁移 SQL 执行与复查、共享表
全部消费仓的 Entity/Mapper/SQL 对账按冻结范围留证；不存在列保持阻塞，不给测试库补
废弃字段绕过。金额、设备、第三方和回调按各自真实入口合同执行。

用户要求全部接口实测时，按 tests.md 的接口×角色×场景矩阵逐项取证，共用健康应用实例
和测试账号；代码/配置或进程健康要求重启时记录原因，并核对当前构建/配置身份。启动、
就绪、日志断言和停止复用原脚本；只清理本任务已核实 owner 的资源并记录零残留。

Mock、测试 Controller、绕鉴权入口仅支持隔离/测试端点结论；HTTP 200、字段非空、
DB-only、编译成功、跳过测试或静态页面配置都不能单独证明真实业务通过。真实前端/外部
入口的载荷、响应、日志和 DB 闭环才能支持对应结论；API/后端集成与浏览器 E2E 分开标注。
字段展示分别记录同 ID 非空 API/DB 对照、历史 NULL 和真实浏览器结果。缺真实参数、
凭据、配置或设备的必测 Case 保留 BLOCKED/PARTIAL，模拟结果另记实际边界。

### Money Precision Boundary

金额相关 Case 按冻结的金额合同记录：恒等式与权威总额、独立计算项、最后差额反推项及
公式、币种/最小单位、计算态来源、中间精度、舍入前后值、最终舍入边界/模式、分配策略
和尾差接收方。验证原始、优惠、实付/退款及分配合计对账、无提前舍入、正数/零/负数或
退款、半分/尾差/多明细、并列余数和幂等重算。权威总额是真源时，最后一项须由总额减
其余项合计得到；全部独立计算后舍入不能证明该合同。汇率场景另留 base/quote、来源及
目标结算舍入证据；展示两位小数不足以证明精度正确。

## 完成前核对

沿 tests.md 的必测及质量门禁逐项核实际证据，任务信号成立才勾选。独立 Tester/Leader
仅在已选模式要求时承担其既有职责，核验原始证据并重跑受影响或合同指定路径。Owner
持续负责其余授权工作，Reviewer 保持只读。历史有效证据可继承其明确版本与范围；
当前源码、入口或上下文变化时按影响取得新证据，旧 PASS 不覆盖新增影响。
